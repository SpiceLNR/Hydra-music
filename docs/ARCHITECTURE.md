# Архитектура Hydra Music

## Слои

1. **Интерфейс (Flutter)**: экраны, кнопки, плеер (media_kit).
2. **Ядро (Rust, `core/`)**: журнал операций, SQLite, правила конфликтов, корзина, имена.
3. **Сеть (iroh, этап 4-5)**: QUIC + TLS 1.3, адресация по ключу устройства, mDNS в локалке,
   пробивание NAT, relay с E2E-шифрованием.

На Android ядро живёт в фоновой службе, на Windows в фоновом процессе с иконкой в трее.

## Файловая система

- Android: `Music/Hydra/<Плейлист>/`
- Windows: `%USERPROFILE%\Music\Hydra\<Плейлист>\`
- Плейлист = папка. Порядок треков хранится в скрытом `.<Плейлист>.json` (точка в имени на Android,
  атрибут Hidden на Windows), треки в нём указаны по UUID.
- Один трек = один физический файл. Перемещение между плейлистами = перенос файла + операция `move`.
- Загрузка идёт во временную скрытую папку, проверяется по SHA-256 и одним действием переименовывается
  в плейлист. Пока файл не загружен на 100%, плеер и проводник его не видят.
- Имена очищаются (`naming.rs`): запрещённые символы, хвостовые точки, зарезервированные имена Windows,
  Unicode NFC, сравнение без учёта регистра.

## Идентичность файла

UUID трека присваивается приложением при первом добавлении; название и теги читаются **только тогда**.
Хэш содержимого нужен лишь для проверки целостности, поэтому правка обложки не «создаёт новый файл».
Переименование в проводнике не влияет на идентичность.

## Журнал и конфликты (`journal.rs`)

- Операции: `add`, `move`, `delete`, `edit`. У каждой: UUID, гибридная метка (HLC), ID устройства.
- Состояние трека = проигрывание всех его операций по порядку меток. Отсюда:
  - повторная доставка безопасна (идемпотентность по `op_id`);
  - порядок доставки не важен (`move` раньше `add` дожидается `add`);
  - конфликт решает более поздняя метка («по дате»), но метки устойчивы к расхождению часов;
  - устройства сходятся к одному состоянию независимо от порядка обмена.
- Удаление = корзина на 30 дней. Более поздняя правка или перемещение возвращает трек из корзины.
- Действия пользователя в плеере (удаление, перемещение) требуют подтверждения; удаления,
  пришедшие по синхронизации, повторно не спрашиваются, но тоже идут в корзину.

## Порядок воспроизведения (`order.rs`)

- У каждого трека есть **ключ порядка** внутри плейлиста: строка из символов `0-9a-z`
  (дробная индексация). Чтобы поставить трек между двумя соседями, считается ключ строго между
  их ключами; остальные треки не затрагиваются.
- Перестановка = одна операция журнала `reorder` с новым ключом, поэтому она синхронизируется
  как любое другое действие: идемпотентно и в любом порядке доставки. При одновременных
  перестановках побеждает более поздняя операция по каждому треку; итоговый порядок на всех
  устройствах одинаков.
- Если два устройства одновременно добавили треки и получили одинаковый ключ, порядок
  определяется по `track_id` (одинаково везде). Следующая перестановка рядом с такими треками
  запускает **перебалансировку**: затронутым трекам выдаются свежие равномерные ключи.
- `add` ставит трек в конец плейлиста; `move` может указать позицию в целевом плейлисте.
- Плеер играет треки строго в этом порядке. Скрытый `.<Плейлист>.json` содержит список UUID в
  порядке воспроизведения и **перегенерируется** из журнала после каждой синхронизации
  (источник правды - журнал, а не файл).
- Перестановка не возвращает из корзины трек, удалённый на другом устройстве.

## Протокол обмена (этап 4)

1. Устройства соединяются и проверяют ключи по подписанному списку семьи.
2. Обмениваются новыми операциями журнала (`ops_since`), не файлами.
3. Каждое устройство само решает, что докачать, и просит файл у **одного** источника (нет двойной отправки).
4. В обе стороны параллельно может идти сколько угодно файлов.

## Семья устройств и безопасность

- ID устройства = публичный ключ (Ed25519), создаётся на устройстве, хранится в Keystore / DPAPI.
- Семья = подписанный список устройств; любое устройство может добавить или отозвать другое,
  после отзыва ключ семьи ротируется.
- Сопряжение только в локальной сети: QR с одноразовым секретом на 2-3 минуты, запасная ссылка
  (только из частных адресов), 6-значный проверочный код на обоих экранах.
- Соединения принимаются только от устройств из списка семьи.
