# Hydra Music architecture

**English** · [Русский](ARCHITECTURE.ru.md)

How the app actually works (from the code, version 0.34). Change history is in
[CHANGELOG.md](../CHANGELOG.md), the user-facing description in [README.md](../README.md).

## Layers

| Layer | Where | What it does |
|---|---|---|
| Interface | `app/` (Flutter) | screens, player, network polling, auto-update, platform parts |
| Bridge | `ffi/` (Rust, `cdylib`) | a single C function `hydra_call(json) -> json` (+ `hydra_free`); methods are dispatched in `ffi/src/lib.rs` |
| Core | `core/` (Rust, `hydra_core`) | library on disk, operation journal, SQLite, trash, tags, network and sync |

- Core calls from Dart run in a separate isolate (`Core.call`); core state is shared per process,
  library access is serialized by a mutex. A panic in the core becomes an error reply.
- Player: on Windows `media_kit` (libmpv), on Android `just_audio` (system ExoPlayer) and
  `audio_service` (background playback, notification, lock screen, headset).
- The core runs inside the app process. On Android the process is kept alive by the foreground
  service `SyncService` (during sync and in auto-sync “standby”), on Windows by the panel window
  with a tray icon.

## Interface languages (`app/lib/l10n/`)

- Russian is the source language: interface strings are written in code as `tr('Russian text',
  {'x': value})` (placeholder `{x}`); numbers with words use `plural(n, one, few, many)`.
- English and Ukrainian come from `strings_en.dart` / `strings_uk.dart`, generated by
  `tools/i18n.py` from a single dictionary; the generator checks that every `tr(...)` string has a
  translation and that placeholders match. `app/test/l10n_test.dart` fails CI if a translation is
  missing.
- `L10n` stores the choice (“same as system”, `ru`, `en`, `uk`) in app preferences; a system
  language other than the three means English. Changing the language rebuilds the widget tree
  (`MaterialApp` is keyed by the language); the tray menu and the Android notification follow it.
- Core messages (errors, network log) are translated the same way: in Rust they are written as
  `tr("Russian text")` or `trf("text {name}", &[("name", &value)])` (`core/src/i18n.rs`); English and
  Ukrainian come from `core/src/i18n_table.rs`, generated by `tools/i18n_core.py`. The app sets the
  core language with the bridge method `set_lang` at startup and on every change. A core test fails
  if a string has no translation, placeholders differ or a log detail line loses its `#` mark. Core
  tests never change the process language: they check translations with `translate(lang, text)`.

## Files and folders

### Library (music)

- Default Android `Music/Hydra`, Windows `%USERPROFILE%\Music\Hydra`. The folder can be moved
  (`library/relocate.rs`, Settings → Folder): everything moves, including `.hydra/`. The chosen
  location is remembered in app data (`library_root.txt`) and on Android also in
  `Music/.hydra-root`, to survive reinstalling.
- Playlist = folder, track = one physical file. Playlist folders contain nothing but music.
- All service data lives in the hidden `.hydra/` in the root (dot name on Android, Hidden attribute
  on Windows):

| Path | What |
|---|---|
| `.hydra/playlists/<playlist id>.json` | manifest: track UUIDs in playback order (write-only, the journal is the source of truth) |
| `.hydra/playlists.json` | playlist order (restored after reinstalling) |
| `.hydra/trash/<track id>/` | trash: the file and `item.json` (the trash is restored from it after reinstalling) |
| `.hydra/meta.json` | title, artist and cover edits that could not be written into the file (keyed by file hash) |
| `.hydra/covers/<sha256>.jpg` | covers for files that cannot embed them; unused ones are removed at scan (older than an hour) |
| `.hydra/images/<playlist>/` | images found in playlist folders (`folder.jpg` etc.) are moved here |
| `.hydra/tmp/` | copies during tag edits and partially downloaded files (`<id>.part`) |
| `.hydra/tags-reread-1` | marker: tags of tracks without a title were already re-read (once) |

- Before 0.31.0 the trash (`.trash/`), playlist order (`.playlists.json`) and manifests
  (`.<Playlist>.json` in the folder) lived among the music; they are moved when the library opens
  (`migrate_service_files`).
- A file from another device is downloaded to `.hydra/tmp/<id>.part`, verified by SHA-256 and moved
  into the playlist with a single rename: a partial file is visible neither to the player nor to the
  file manager.
- Names are cleaned (`naming.rs`): forbidden characters, trailing dots, reserved Windows names,
  Unicode NFC; comparison is case-insensitive.

### Formats and tags

- Only formats that play on both mpv and ExoPlayer are picked up (`naming::is_supported_audio`):
  mp3, flac, wav, ogg/oga/opus, m4a/m4b/mp4, aac, mka, plus the video containers mkv, webm, mov, m4v
  (played as audio). WMA, APE, WavPack, AIFF, AVI are not picked up; tracks of these formats added
  before 0.33.0 are not treated as missing (`is_dropped_format`).
- Tags (lofty) are read by file content, not extension, in relaxed mode: a broken field is skipped
  instead of rejecting the whole file (`tags::read_tagged`).
- Tag edits are safe: a copy in `.hydra/tmp` is changed, re-read, and only then replaces the
  original. If writing is impossible (Matroska/WebM, error), the edit stays in the journal and in
  `meta.json`.

### App data (outside the library)

`hydra.db` (SQLite: journal and state), `device_id`, `identity.json` (Noise key and the chosen device
name), `family.json` (paired devices), `goodbye.json` (unsent removal notices), `iroh.key` (key for
internet connections), `library_root.txt`. All of this is lost on reinstall; the library and
`.hydra/` remain.

## Track identity

- A track's UUID is assigned when it is first added and stored in the database, not in the file
  name.
- The content SHA-256 is used to verify transfers, to recognize moves and renames done outside the
  app (a missing track is found by hash elsewhere → `move`, not “deleted + added”), to merge
  duplicates (`merge_duplicates`) and as the `meta.json` key.
- Tags are read when a new file is added (and once when re-reading tracks without a title).

## Journal and conflicts (`journal.rs`, `clock.rs`)

- Track operations (`ops`): `add`, `move`, `delete`, `edit` (title, artist, hash, cover), `reorder`.
  Playlist operations (`pl_ops`): create, rename, delete, order, sort rule. Every operation has a
  UUID, a hybrid logical timestamp (HLC) and a device id.
- State = replaying operations by timestamp: redelivery is safe (by `op_id`), delivery order does not
  matter, the later timestamp wins a conflict; HLC tolerates clock drift.
- Deletion = trash for 30 days. A later edit or move brings a track back from the trash. The trash is
  shared: deletions are visible on all devices, restoring happens on the device that owns the file.
  Deletions from another device for files we never had do not enter the trash.
- Mass deletion protection: if a playlist folder or 5 or more of its files disappear outside the app,
  the deletion is not recorded until the user chooses “Get back from other devices” or “Delete
  everywhere” (`held_deletions` / `resolve_held`).
- Journal compaction (`journal::compact`, once a day when >1000 entries): operations fully overridden
  by later ones are dropped; the newest operation of every device is kept. Checked with random
  histories: the state before and after is identical.

## Playback order (`order.rs`)

- A track has an order key within the playlist — a string of `0-9a-z` (fractional indexing):
  inserting between neighbours = a key strictly between theirs, other tracks are untouched.
- Reordering = one `reorder` operation. With equal keys (simultaneous adds on two devices) the order
  is decided by `track_id`; the next reorder nearby rebalances the keys.
- Playlist rule: “any order” (manual), “by artist”, “by title”. A sorted playlist places new tracks
  automatically (`resort_playlist`); manual reordering switches the rule to “any order”.

## Network (`net/`)

- **Local network:** TCP 47475, an encrypted Noise channel (`snow`):
  `Noise_XX_25519_ChaChaPoly_SHA256` for known devices, `Noise_XXpsk3_…` during pairing (one-time
  secret from the QR code). Device discovery — UDP 47476, broadcast `HYDRA1|<device_id>|<port>`.
- **Internet:** iroh (QUIC) with a separate key `iroh.key`; the device address = iroh node id. Lookup
  by key via n0 DNS, connection directly or via relay. By default the n0 relays (`presets::N0`); a
  custom one can be set (`net_set_relay`): the connection restarts with the same key, the device
  address does not change.
- Sessions run one at a time (the `session` lock in `Node`); an incoming connection during a session
  is rejected. There is no global mutable state in `net/`: tests run in parallel in one process.

### Sync session (`session.rs`, `library/sync.rs`)

1. `Hello`: `proto`, `device_id`, `name`, `port`, `endpoint` (iroh address), `goodbye`. New fields use
   `#[serde(default)]` so older versions understand newer ones. The device name is updated on the
   peer at every meeting.
2. Inventory (`sync_inventory`) and “adoption” of shared ids (`sync_adopt`): the same playlist by name
   and the same file by hash get one id on both devices.
3. Exchange of missing journal operations (`sync_vector` / `sync_batch_for`) and applying them
   (`sync_apply`); files not yet present are marked `pending`.
4. File download (`sync_needs` → `sync_file_for` → `sync_store_file`): each file is requested from one
   source; covers travel the same channel as a “file” `cover:<sha>`. The sender fixes an outdated
   hash itself if its file has changed.

The initiator speaks first, then the responder (no mutual blocking on large messages).

### Family and pairing (`identity.rs`, `node.rs`)

- The device key is X25519 (Noise) in `identity.json`, together with the name chosen in Settings.
- The family is `family.json`: id, name (and our own label for the device, visible only to us), public
  key, last address, iroh address, sync time. Connections are accepted only from family keys.
- Pairing: the link `hydra://pair?k=<key>&s=<secret>&a=<addresses>&e=<iroh address>[&p=<port>]` in a
  QR code (32-byte values in base64url, the standard port is omitted; old hex links are still read).
  The secret is single-use and valid for 3 minutes. Fallbacks: open the link with the camera or paste
  it manually.
- Removing a device works both ways: the peer receives `goodbye`; if it is unreachable, the notice
  waits up to 14 days in `goodbye.json`.

## Platform parts

- **Android:** `MainActivity` (generated by `tools/patch_android_manifest.py`) — channels
  `hydra/sync_service` (service, battery, pairing links) and `hydra/update` (installing an update via a
  `PackageInstaller` session). Permissions, services and `hydra://pair` links are added by the same
  script.
- **Windows:** the panel at the screen edge (`window_manager`, custom frame `win32_frame.dart`), tray
  icon (`tray_manager` 0.5.x; the close button collapses, “Exit” is in the icon menu), autostart — a
  value in `HKCU\…\Run` (core, `winreg` crate); with `--autostart` the window starts collapsed.

## Update (`app/lib/updater.dart`)

- Check: `version-windows.json` / `version-android.json` from Releases `latest` (version, commit,
  size, SHA-256) on start, every 6 hours, by the button in Settings, and on Windows when the panel
  expands (at most hourly). Only CI builds update.
- Resumable download (`<version>.<ext>.part`), SHA-256 check.
- **Windows:** the archive is unpacked into `app.new` next to the program folder; “Install” starts a
  PowerShell script via the bridge's `spawn_hidden` (`CREATE_NO_WINDOW`, working directory outside
  `app`) and closes the program; the script swaps `app` → `app.prev`, `app.new` → `app` and starts the
  new version (putting the old one back on failure). Log — `app.update\install.log`.
- **Android:** the APK in the app's internal folder, installed by the system installer.
- Downloaded files are removed on the first start of the new version; only `app.prev` (one copy) and
  the install log remain.

## Build and signing (`.github/workflows/ci.yml`)

- `core-tests` (core and bridge tests), `android-apk` (analysis, Dart tests, release APK),
  `windows-build`. The platform folders `app/android` and `app/windows` are not stored in the
  repository: CI creates them with `flutter create` and patches them with the script. Builds retry up
  to three times on network failures (the Windows step runs in PowerShell, not bash).
- The APK is signed with a permanent key from the secret `HYDRA_KEYSTORE_B64` (the path is passed to
  Gradle explicitly); before publishing CI checks the signature fingerprint against the key. Builds
  and `version-*.json` are published to Releases `latest` (the file first, then the description).
