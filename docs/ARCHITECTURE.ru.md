# Архитектура Hydra Music

[English](ARCHITECTURE.md) · **Русский**

Как устроено приложение на самом деле (по коду, версия 0.33). История изменений — в
[CHANGELOG.ru.md](../CHANGELOG.ru.md), описание для пользователя — в [README.ru.md](../README.ru.md).

## Слои

| Слой | Где | Что делает |
|---|---|---|
| Интерфейс | `app/` (Flutter) | экраны, плеер, опрос сети, автообновление, платформенные части |
| Мост | `ffi/` (Rust, `cdylib`) | одна C-функция `hydra_call(json) -> json` (+ `hydra_free`); методы разбираются в `ffi/src/lib.rs` |
| Ядро | `core/` (Rust, `hydra_core`) | библиотека на диске, журнал операций, SQLite, корзина, теги, сеть и синхронизация |

- Вызовы ядра из Dart идут в отдельном изоляте (`Core.call`), состояние ядра общее на процесс,
  доступ к библиотеке сериализуется мьютексом. Паника в ядре превращается в ответ с ошибкой.
- Плеер: на Windows `media_kit` (libmpv), на Android `just_audio` (системный ExoPlayer) и
  `audio_service` (фоновое воспроизведение, уведомление, экран блокировки, гарнитура).
- Ядро работает в процессе приложения. На Android процесс держит служба переднего плана
  `SyncService` (во время синхронизации и в режиме «дежурства» автосинхронизации), на Windows —
  окно-шторка со значком в трее.

## Файлы и папки

### Библиотека (музыка)

- По умолчанию Android `Music/Hydra`, Windows `%USERPROFILE%\Music\Hydra`. Папку можно перенести
  (`library/relocate.rs`, «Настройки» → «Папка»): переезжает всё, включая `.hydra/`. Выбранное
  место запоминается в данных приложения (`library_root.txt`), на Android ещё и в
  `Music/.hydra-root`, чтобы пережить переустановку.
- Плейлист = папка, трек = один физический файл. В папках плейлистов нет ничего служебного.
- Всё служебное — в скрытой `.hydra/` в корне (точка в имени на Android, атрибут Hidden на Windows):

| Путь | Что |
|---|---|
| `.hydra/playlists/<id плейлиста>.json` | манифест: UUID треков в порядке воспроизведения (только пишется, источник правды — журнал) |
| `.hydra/playlists.json` | порядок плейлистов (возвращается после переустановки) |
| `.hydra/trash/<id трека>/` | корзина: файл и `item.json` (по нему корзина восстанавливается после переустановки) |
| `.hydra/meta.json` | правки названия, исполнителя и обложки, которые не удалось записать в файл (ключ — хэш файла) |
| `.hydra/covers/<sha256>.jpg` | обложки для файлов, в которые их не встроить; ненужные убираются при скане (старше часа) |
| `.hydra/images/<плейлист>/` | картинки, найденные в папках плейлистов (`folder.jpg` и т. п.), переносятся сюда |
| `.hydra/tmp/` | копии при правке тегов и недокачанные файлы (`<id>.part`) |
| `.hydra/tags-reread-1` | метка: теги треков без названия уже перечитаны (один раз) |

- До 0.31.0 корзина (`.trash/`), порядок плейлистов (`.playlists.json`) и манифесты
  (`.<Плейлист>.json` в папке) лежали среди музыки; при открытии библиотеки они переносятся
  (`migrate_service_files`).
- Файл с другого устройства качается в `.hydra/tmp/<id>.part`, сверяется по SHA-256 и одним
  переименованием встаёт в плейлист: недокачанный файл не виден ни плееру, ни проводнику.
- Имена очищаются (`naming.rs`): запрещённые символы, хвостовые точки, зарезервированные имена
  Windows, Unicode NFC; сравнение без учёта регистра.

### Форматы и теги

- Подхватываются только форматы, которые играют и на mpv, и на ExoPlayer
  (`naming::is_supported_audio`): mp3, flac, wav, ogg/oga/opus, m4a/m4b/mp4, aac, mka, а также
  видеоконтейнеры mkv, webm, mov, m4v (играют звуком). WMA, APE, WavPack, AIFF, AVI не подхватываются;
  треки этих форматов, добавленные до 0.33.0, не считаются пропавшими (`is_dropped_format`).
- Теги (lofty) читаются по содержимому файла, а не по расширению, и в мягком режиме: испорченное поле
  пропускается, а не отвергает весь файл (`tags::read_tagged`).
- Правка тегов безопасна: меняется копия в `.hydra/tmp`, копия перечитывается и только потом заменяет
  оригинал. Если записать нельзя (Matroska/WebM, ошибка), правка остаётся в журнале и в `meta.json`.

### Данные приложения (не в библиотеке)

`hydra.db` (SQLite: журнал и состояние), `device_id`, `identity.json` (ключ Noise и выбранное имя
устройства), `family.json` (сопряжённые устройства), `goodbye.json` (неотправленные уведомления об
удалении), `iroh.key` (ключ для связи через интернет), `library_root.txt`. Всё это пропадает при
переустановке; библиотека и `.hydra/` остаются.

## Идентичность трека

- UUID трека присваивается при первом добавлении и хранится в базе, не в имени файла.
- SHA-256 содержимого нужен для проверки целостности при передаче, для распознавания переноса и
  переименования вне приложения (пропавший трек находится по хэшу в другом месте → `move`, а не
  «удалён + добавлен»), для слияния дублей (`merge_duplicates`) и как ключ `meta.json`.
- Теги читаются при добавлении нового файла (и один раз при перечитывании треков без названия).

## Журнал и конфликты (`journal.rs`, `clock.rs`)

- Операции треков (`ops`): `add`, `move`, `delete`, `edit` (название, исполнитель, хэш, обложка),
  `reorder`. Операции плейлистов (`pl_ops`): создание, переименование, удаление, порядок, правило
  сортировки. У каждой операции UUID, гибридная метка времени (HLC) и id устройства.
- Состояние = проигрывание операций по меткам: повторная доставка безопасна (по `op_id`), порядок
  доставки не важен, при конфликте побеждает более поздняя метка; HLC устойчивы к расхождению часов.
- Удаление = корзина на 30 дней. Более поздняя правка или перемещение возвращает трек из корзины.
  Корзина общая: удалённое видно на всех устройствах, восстановление — у владельца файла. Удаления
  с другого устройства без файла у нас в корзину не попадают.
- Защита от массового удаления: если вне приложения пропала папка плейлиста или 5 и больше его
  файлов, удаление не записывается, пока пользователь не выберет «Вернуть с других устройств» или
  «Удалить везде» (`held_deletions` / `resolve_held`).
- Сжатие журнала (`journal::compact`, раз в сутки при >1000 записей): убираются операции, целиком
  перекрытые более поздними; самая новая операция каждого устройства остаётся. Проверяется
  случайными историями: состояние до и после совпадает.

## Порядок воспроизведения (`order.rs`)

- У трека есть ключ порядка внутри плейлиста — строка из `0-9a-z` (дробная индексация): вставка
  между соседями = ключ строго между их ключами, остальные треки не меняются.
- Перестановка = одна операция `reorder`. При одинаковых ключах (одновременное добавление на двух
  устройствах) порядок задаёт `track_id`; следующая перестановка рядом перебалансирует ключи.
- Правило плейлиста: «как попало» (ручной порядок), «по исполнителю», «по названию». Отсортированный
  плейлист сам ставит новые треки на место (`resort_playlist`); ручная перестановка переключает
  правило в «как попало».

## Сеть (`net/`)

- **Локальная сеть:** TCP 47475, шифрованный канал Noise (`snow`): `Noise_XX_25519_ChaChaPoly_SHA256`
  для знакомых устройств, `Noise_XXpsk3_…` при сопряжении (одноразовый секрет из QR). Поиск устройств —
  UDP 47476, широковещательное `HYDRA1|<device_id>|<port>`.
- **Интернет:** iroh (QUIC) с отдельным ключом `iroh.key`; адрес устройства = id узла iroh. Поиск по
  ключу через DNS n0, соединение напрямую или через relay. По умолчанию relay-серверы n0
  (`presets::N0`), можно указать свой (`net_set_relay`): связь перезапускается с тем же ключом, адрес
  устройства не меняется.
- Сеансы идут по одному (замок `session` в `Node`); входящее подключение во время сеанса отклоняется.
  Глобального изменяемого состояния в `net/` нет: тесты идут параллельно в одном процессе.

### Сеанс синхронизации (`session.rs`, `library/sync.rs`)

1. `Hello`: `proto`, `device_id`, `name`, `port`, `endpoint` (адрес iroh), `goodbye`. Новые поля — с
   `#[serde(default)]`, чтобы старые версии понимали новые. Имя устройства обновляется у собеседника
   при каждой встрече.
2. Опись (`sync_inventory`) и «усыновление» общих id (`sync_adopt`): одинаковый плейлист по имени и
   одинаковый файл по хэшу получают один id на обоих устройствах.
3. Обмен недостающими операциями журнала (`sync_vector` / `sync_batch_for`) и их применение
   (`sync_apply`); файлы, которых ещё нет, помечаются `pending`.
4. Докачка файлов (`sync_needs` → `sync_file_for` → `sync_store_file`): каждый файл просят у одного
   источника, обложки едут тем же каналом как «файл» `cover:<sha>`. Отправитель сам чинит устаревший
   хэш, если файл у него изменился.

Говорит сначала инициатор, потом отвечающий (без взаимной блокировки на больших сообщениях).

### Семья и сопряжение (`identity.rs`, `node.rs`)

- Ключ устройства — X25519 (Noise) в `identity.json`; там же имя, выбранное в настройках.
- Семья — `family.json`: id, имя (и своё название для устройства, видимое только у нас), публичный
  ключ, последний адрес, адрес iroh, время синхронизации. Соединения принимаются только от ключей
  из семьи.
- Сопряжение: ссылка `hydra://pair?k=<ключ>&s=<секрет>&a=<адреса>&e=<адрес iroh>[&p=<порт>]` в QR-коде
  (32-байтные значения в base64url, стандартный порт не пишется; старые hex-ссылки тоже читаются).
  Секрет одноразовый, действует 3 минуты. Резервные способы — открыть ссылку камерой или вставить вручную.
- Удаление устройства действует на обе стороны: собеседнику уходит `goodbye`; если он недоступен,
  уведомление ждёт до 14 дней в `goodbye.json`.

## Платформенные части

- **Android:** `MainActivity` (генерируется `tools/patch_android_manifest.py`) — каналы
  `hydra/sync_service` (служба, батарея, ссылки сопряжения) и `hydra/update` (установка обновления
  сеансом `PackageInstaller`). Разрешения, службы и ссылки `hydra://pair` дописывает тот же скрипт.
- **Windows:** шторка у края экрана (`window_manager`, своя рамка `win32_frame.dart`), значок в трее
  (`tray_manager` 0.5.x; крестик сворачивает, «Выход» — в меню значка), автозапуск — строка в
  `HKCU\…\Run` (ядро, крейт `winreg`), при запуске с `--autostart` окно свёрнуто.

## Обновление (`app/lib/updater.dart`)

- Проверка: `version-windows.json` / `version-android.json` из Releases `latest` (версия, коммит,
  размер, SHA-256) при запуске, раз в 6 часов, кнопкой в настройках, на Windows ещё при
  разворачивании шторки (не чаще раза в час). Обновляются только сборки из CI.
- Загрузка с докачкой (`<версия>.<ext>.part`), сверка SHA-256.
- **Windows:** архив распаковывается в `app.new` рядом с папкой программы; «Установить» запускает
  PowerShell-скрипт через `spawn_hidden` моста (`CREATE_NO_WINDOW`, текущая папка вне `app`) и
  закрывает программу; скрипт меняет `app` → `app.prev`, `app.new` → `app` и запускает новую версию
  (при неудаче возвращает прежнюю). Журнал — `app.update\install.log`.
- **Android:** APK во внутренней папке приложения, установка системным установщиком.
- Скачанные файлы удаляются при первом запуске новой версии; остаются только `app.prev` (одна копия)
  и журнал установки.

## Сборка и подпись (`.github/workflows/ci.yml`)

- `core-tests` (тесты ядра и моста), `android-apk` (анализ, тесты Dart, release-APK), `windows-build`.
  Платформенные папки `app/android` и `app/windows` в репозитории не хранятся: CI создаёт их
  `flutter create` и патчит скриптом.
- APK подписывается постоянным ключом из секрета `HYDRA_KEYSTORE_B64` (путь передаётся Gradle явно);
  перед публикацией CI сверяет отпечаток подписи с ключом. Сборки и `version-*.json` выкладываются в
  Releases `latest` (сначала файл, потом описание).
