# Hydra Music: заметки для Claude Code

Личный аудиоплеер с открытым исходным кодом (Android и Windows). Автор: SpiceLNR.
Лицензия: PolyForm Noncommercial 1.0.0 (форки можно, продавать нельзя).
Общаемся с автором **по-русски**, коротко и по делу. Все тексты в приложении, README, хронике и комментарии кода по-русски.

## Как устроен проект
- `core/` — Rust-ядро (`hydra_core`): гибридные логические часы (HLC), журнал операций (`journal.rs`, `ops` и `pl_ops`), SQLite, библиотека и корзина (`library.rs`, `library/sync.rs`), имена файлов, порядок треков, теги, сеть (`net/`: Noise XX/XXpsk3, поиск устройств по UDP, iroh для связи через интернет).
- `ffi/` — C-интерфейс ядра для Flutter: единственная функция `hydra_call(json) -> json`, методы разбираются в `ffi/src/lib.rs`.
- `app/` — Flutter: экраны Android и Windows, плеер, `net_service.dart` (опрос сети и автосинхронизация), `library_controller.dart`.
- `tools/` — `patch_android_manifest.py` (разрешения, службы, ссылки `hydra://pair` в сгенерированном Android-проекте), `local_build.bat`.
- `docs/ARCHITECTURE.md` — устройство журнала, порядка треков и протокола.
- Папки `app/android` и `app/windows` в репозитории **не хранятся**: CI создаёт их командой `flutter create ... --org com.spicelnr` и патчит скриптом.

## Главная идея
Плейлист — настоящая папка `Music/Hydra/<Плейлист>` (на Windows `Музыка\Hydra`). У каждого трека UUID (в базе, не в имени файла). Удалённое лежит в скрытой `.trash` 30 дней. Устройства синхронизируются по Wi-Fi или через интернет после сопряжения по QR. Состояние трека получается «проигрыванием» операций по меткам HLC (последняя по времени побеждает), поэтому доставка идемпотентна и порядок не важен.

## Правила работы
1. **Каждое изменение = новая версия** `0.N.M` (`N` — новая возможность, `M` — исправление). Обновляй номер в четырёх местах: `app/pubspec.yaml`, `core/Cargo.toml`, `ffi/Cargo.toml`, `app/lib/build_info.dart` (`kVersion`), и добавляй раздел **сверху** в `CHANGELOG.md` (дата и список изменений по-русски; пометка «не проверено», пока автор не подтвердил на устройствах).
2. Перед коммитом: `rustfmt --edition 2021` для изменённых `.rs`, затем `cd core && cargo test --all-features` (и в `ffi`, если менял мост). В CI запускаются те же тесты; параллельные тесты живут в одном процессе, поэтому **никакого глобального изменяемого состояния** в `net/` (однажды это уронило соседний тест).
3. Меняешь протокол или формат данных (`Hello`, операции, `family.json`, `goodbye.json`) — сохраняй обратную совместимость (`#[serde(default)]`) и пиши об этом в хронике.
4. Тесты на каждую правку логики синхронизации, журнала и корзины. Сжатие журнала (`journal::compact`) проверяется случайными историями: состояние до и после должно совпадать.
5. Если пользователь прислал архив `fix-*.zip` / `feature-*.zip`: распакуй поверх репозитория, текст из `CHANGELOG-<версия>.txt` вставь в `CHANGELOG.md` (под первой строкой `---`, поменяй «Текущая версия»), сам txt удали. Если Flutter не установлен, `flutter analyze` пропусти и скажи об этом: сборку проверит CI.
6. README и `CHANGELOG.md` держи в соответствии с кодом. Раздел «Что ещё не сделано» в README — это список задач.
7. Коммиты: короткое сообщение с номером версии, например `0.22.2: ...`. Пушим в `main`; CI собирает APK и Windows-сборку и выкладывает их в Releases (тег `latest`).
8. Не коммить `Cargo.lock`, ключи (`*.keystore`, `*.jks`), `identity.json`, `hydra.db`: они в `.gitignore`. Ключ подписи Android лежит в секрете GitHub `HYDRA_KEYSTORE_B64`.
9. В PowerShell автора нет `&&` и по умолчанию `>>` пишет в UTF-16: для файлов используй редактор, а не `echo >>`.

## Оформление интерфейса
Стиль Windows Phone / Metro: плоский, зелёный `#60A917`, только кнопки и списки, без скруглений и теней. Режим «Анархия» перекрашивает элементы плеера в красный.

## Сеть и синхронизация (коротко)
- TCP 47475 (обмен), UDP 47476 (поиск). Сеансы идут по одному (замок `session` в `Node`), входящее подключение во время другого сеанса отклоняется.
- Сопряжение: одноразовый секрет из QR (3 минуты). Дальше устройства узнают друг друга по ключу (`family.json`).
- Удаление устройства сообщает второй стороне (`goodbye`), если недоступна, сообщение хранится 14 дней (`goodbye.json`).
- Журнал сети в приложении (кнопка справа вверху экрана «Устройства») пишет подробности: описи, принятые операции, нужные файлы, скорость, отклонённые файлы. По нему разбираем проблемы.

## Что сделано с версии 0.22 (подробности в `CHANGELOG.md`)
- 0.22.x: «Кадрография» и прочие зависшие файлы: журнал исправляется по файлу, отправитель сам чинит устаревший хэш.
- 0.23.x: перенос папки библиотеки (`move_root`, указатель корня `library_root.txt` и `/storage/emulated/0/Music/.hydra-root`), общая корзина (удалённое видно на всех устройствах, восстановление у владельца файла).
- 0.24.0: правки названия и исполнителя у файлов без тегов хранятся в `.hydra/meta.json` и переживают переустановку.
- 0.25.0–0.25.2: обложки как отдельные файлы `.hydra/covers/<sha>.jpg`, их синхронизация (`cover:<sha>`), автосинхронизация после правок (`syncSoon`).
- 0.25.3: слияние дублей при `scan` (`merge_duplicates`, Delete с `duplicate_of`), защита общего файла от переноса в корзину, сброс кэша обложек в приложении. Проверено автором.
- 0.25.4: APK подписывается ключом из секрета явно (`HYDRA_KEYSTORE` в `build.gradle.kts` через `patch_android_manifest.py`), CI падает, если отпечаток подписи APK не совпадает с ключом из секрета. Раньше секрет фактически не использовался, ключ сменился вместе с образом раннера, и приложение на телефоне пришлось один раз переустановить.
- 0.26.0: автообновление на Windows (`updater.dart`, `widgets/update_banner.dart`): `version-windows.json` из `latest` при запуске и раз в 6 часов, плашка внизу шторки, загрузка с докачкой, SHA-256, распаковка в `app.new`, установка скриптом PowerShell (`app` → `app.prev`, `app.new` → `app`, журнал `app.update\install.log`). Только сборки из CI (`kBuild != 'локальная'`).
